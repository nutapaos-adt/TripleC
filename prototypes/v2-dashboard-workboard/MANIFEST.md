# v2-dashboard-workboard

วันที่: 2026-11-27

## อะไรอยู่ในโฟลเดอร์นี้
| ไฟล์ | สิ่งที่แสดง |
|---|---|
| `dashboard-workboard.html` | หน้า "ภาพรวมทีมเยี่ยมบ้าน" แบบหน้างาน (work board) หน้าเดียว คลิกได้ ใช้ข้อมูลสมมติทั้งหมด |

## ที่มา
ผู้ใช้ (พยาบาลทีมเยี่ยมบ้าน) ขอให้ทบทวนหน้า dashboard ทั้งหน้า และทำตัวอย่างที่ "เห็นสิ่งที่ต้องทำชัดขึ้น ข้อมูลไม่เยอะเกินไป"
ข้อมูลประกอบ: ทีมมี 4 คน (พยาบาล 1 + ผู้ช่วย 3 ที่ไม่กล้าปิดเคส ต้องรอพยาบาล) / AI ช้าจนผู้ช่วยข้ามขั้นวิเคราะห์ /
รอเยี่ยมในเขตยังไม่ชัด / งานกระจายหลายเมนู — วิเคราะห์จากหน้า dashboard จริง (Laravel) ที่ใช้อยู่ ณ วันที่ 27 พ.ย. 2569

## ต่างจาก v1 (`v1-full-coc-flow/dashboard.html`) อย่างไร
v2 เป็นการจัดโครงหน้าใหม่ ไม่ใช่การแก้เล็กน้อย จึงแยกโฟลเดอร์ใหม่เพื่อเทียบข้างกันได้
- **ตัวเลขสรุปเดิมครบทั้ง 4 ช่อง** (ผู้ป่วยในการดูแล / รอเยี่ยม แยกในเขต-นอกเขต และโทรติดตาม / เคสที่เยี่ยมวันนี้ / ผู้ป่วย TKA พร้อมช่องกดดูรายชื่อ และตัวเลือกเดือน) **อยู่บนสุดของหน้าเหมือนเดิม ไม่พับ ไม่ตัดตัวเลขใดออก** ตามที่ผู้ใช้ขอ (รอบแรกเคยย่อเหลือ 3 ก้อน พับ และย้ายไปล่างสุด — ผู้ใช้แจ้งว่าต้องการตัวเลขเดิมครบและส่วนนี้ต้องอยู่บนสุดเหมือนเดิม จึงแก้) ใต้ตัวเลขสรุปคือแถบเตือน แล้วตามด้วยช่องงานที่ต้องทำ
- แถบเตือนบนสุด: บ้านแดงไม่มีนัดถัดไป / ผลที่ AI พบเสี่ยงรอยืนยัน
- ช่องงาน 4 ช่องกดได้ สีแดง = ล่าช้าชัดเจน (เกินกำหนด ≥ 3 วัน, ผลเยี่ยมค้าง ≥ 5 วัน, บ้านแดงรอตรวจแผน) ส้ม = มีค้าง เขียว = ไม่มีค้าง
- งานลงพื้นที่ / โทรติดตาม แยกตารางกัน แถวย่อ 2 บรรทัด กดขยายดูรายละเอียด ค่าเริ่มต้นแสดงเฉพาะ "ต้องทำ" (เกินกำหนด + วันนี้ + 7 วัน)
- ตัวกรองเดียวใช้ร่วมกัน + จัดกลุ่มตามตำบล + พิมพ์ใบนัดวันนี้ (A4)
- งานโทรให้เบอร์เป็นอันดับแรก (ปุ่มโทรใหญ่) ไม่แสดงตำบล

## ตัวควบคุมตัวอย่าง (แถบบางใต้ topbar ไม่ใช่ส่วนของระบบ)
- **ระยะ "ทำได้ทันที"** (ค่าเริ่มต้น): ทำได้ด้วยข้อมูลที่มีอยู่ในฐานข้อมูลปัจจุบัน ไม่ต้องรัน SQL
- **ระยะ "ภาพเต็ม"**: เพิ่มของที่ต้องแก้ฐานข้อมูลก่อน (ติดป้าย "ต้องแก้ฐานข้อมูล") ได้แก่ ผู้รับผิดชอบเคส, สถานะนัดญาติ,
  ผลลัพธ์ "โทรไม่ติด N ครั้ง", บทบาทผู้ช่วย (เสนอการตัดสินใจ / พยาบาลอนุมัติทีละหลายรายพร้อมติ๊กยืนยัน)
  - มุมมองพยาบาล: คิว "ผลเยี่ยมรอพยาบาลยืนยัน" มีข้อเสนอของผู้ช่วยและปุ่มอนุมัติที่เลือก (เฉพาะรายที่ AI ไม่พบเสี่ยง + ผู้ช่วยเสนอ "ติดตามซ้ำ"; รายที่ AI พบเสี่ยงหรือเสนอปิดเคส/ส่งต่อ ต้องเปิดตรวจรายละเอียด)
  - มุมมองผู้ช่วย: งานของฉัน, เสนอการตัดสินใจ, **ไม่มีปุ่มยืนยัน/ปิดเคส** (human-in-the-loop: พยาบาลยืนยันเสมอ)

## ตรวจแล้ว
- เปิดบน Chrome จริง: ไม่มี console error ทั้งจอ 1440px และมือถือ 390px
- ไม่มี horizontal scroll ของทั้งหน้าที่ 390px (แถวเปลี่ยนเป็นการ์ดซ้อนบรรทัด)
- ทดสอบสลับ ระยะทำได้ทันที / ภาพเต็ม × พยาบาล / ผู้ช่วย ไม่พัง
- ปรับกติกาสีช่องงานหลังตรวจ: เดิมช่องแดงทั้ง 4 ช่อง ทำให้ไม่เห็นความต่าง

## ข้อควรรู้ / ยังไม่ได้ตัดสินใจ
- คำว่า "ต้องทำ" = เกินกำหนด + วันนี้ + 7 วันข้างหน้า (ตัวเลข 7 วันปรับได้)
- ตัวกรองและจำนวนในตัวกรองรวมงานเยี่ยมบ้านกับโทรติดตามไว้ด้วยกัน (ต้อง 10 = 7 เยี่ยม + 3 โทร)
- สีข้อความเตือน (--color-warning บน tint) ตาม DESIGN.md แต่ contrast ต่ำกว่า AA สำหรับตัวเล็ก — ควรพิจารณาปรับ token ใน DESIGN.md
- ยังไม่ได้ลองพิมพ์ใบนัดบนเครื่องพิมพ์จริง (มี @media print ใน modal)
- **ทำจริงในระบบแล้ว (27 พ.ย. 2569)** เฉพาะระยะ "ทำได้ทันที" ตามที่ผู้ใช้เห็นชอบ — ไม่แยกมุมมองพยาบาล/ผู้ช่วย (ผู้ใช้แจ้งว่าให้ทุกคนเห็นหน้าเดียวกัน) ส่วนที่ต้องแก้ฐานข้อมูล (ผู้รับผิดชอบเคส, นัดญาติ, โทรไม่ติด, บทบาทผู้ช่วย) ยังไม่ทำ
